Why the large false-positive classes are false positives (verified by reading
every flagged site):

* `EI_EXPOSE_REP*` — the configuration/value objects are immutable and return
  immutable collaborators (`List` copies are wrapped in `unmodifiableList`);
  Swing accessors are used by the GUI self-test and must expose the live
  component; `ClassPool` is deliberately mutable during the pass pipeline.
* `NP_NULL_ON_SOME_PATH_FROM_RETURN_VALUE` — the pattern is a duplicated
  `Path.getParent()`/`getFileName()` call (`x.getParent() != null &&
  Files.isDirectory(x.getParent())`) or a guarded accessor. The one site where
  the null was reachable is the audit-owned `Main:278` (fixed, A9). The two
  remaining audit-owned hits (`Main:277`/`:302`) are the same benign duplicated
  accessor pattern (a local variable is checked, then the accessor is called
  again).
* `ICAST_QUESTIONABLE_UNSIGNED_RIGHT_SHIFT` — intentional low-byte extraction
  in ChaCha20 (`(byte)(block[i >>> 2] >>> (8 * (i & 3)))`) and the xorshift
  stream; covered by `CryptoTest` and the runtime wire-format tests.
* `ICAST_INTEGER_MULTIPLY_CAST_TO_LONG` — PE bounds check; the multiplied
  operand is the trusted function count (4), non-overflowing.
* `DMI_RANDOM_USED_ONLY_ONCE` — deterministic one-shot draws seeded from
  `config.seed()`, plus the documented intentional per-build (class-encryption
  key material) and per-load (anti-dump verification order) randomness; no
  build artifact determinism depends on those two.
* `RV_RETURN_VALUE_IGNORED_BAD_PRACTICE` — deliberate best-effort Windows temp
  cleanup (`File.delete` return ignored, failure logged where it matters).
* `DP_CREATE_CLASSLOADER_INSIDE_DO_PRIVILEGED` — verifier class loading; no
  `SecurityManager` on supported JDKs.
* `SIC_INNER_SHOULD_BE_STATIC` — style-only (inner UI row class, no outer
  capture).

## 6. Remaining known risks (accepted)

1. **Duplicate YAML keys are last-wins** (deterministic, tested). The YAML spec
   makes them invalid; a typo that duplicates a key is silently resolved to the
   later value. A future strict mode could warn.
2. **Numeric overflow/malformed typed YAML values fall back to defaults**
   (`intValue`/`longValue` catch `NumberFormatException`); e.g.
   `junkMembers.methods: 99999999999` becomes `2`. Safe defaults, but silent.
3. **Malformed advanced options are silently defaulted** by
   `UmbraConfig.optionInt/optionLong/optionDouble/optionBool` (documented API
   contract) — e.g. `--set decompilerNoise.level=abc` uses the default.
4. **`--set` trims the value** (`key=  a b  ` → `a b`); leading/trailing spaces
   cannot be represented in a `--set` value.
5. **YAML subset limits**: anchors/aliases, multi-document streams, block
   scalars and explicit tags are unsupported (documented). The `#`-comment and
   quote scanners do not track backslash-escaped quotes, so a double-quoted
   scalar containing `\"` before a colon/`#` is parsed conservatively; the
   written config format (double-quoted, fully escaped) round-trips correctly.
6. **License expiry uses the default timezone** (`SimpleDateFormat("yyyy-MM-dd")`);
   a license expiring "today" is valid until local midnight.
7. **SpotBugs accepted risks**: seven `DMI_RANDOM_USED_ONLY_ONCE` sites — five
   deterministic one-shot draws seeded from `config.seed()`, one intentional
   per-build class-encryption key randomness (`ClassEncryptionPass:153`, two
   builds must differ by design) and one intentional per-load anti-dump
   verification-order shuffle (`UmbraClassLoader:1025`); single-shot
   `System.exit` in the GUI `--run` mode; dead fields/branches in audit-owned
   classes (`InspectTool$Report.multiReleaseAttribute`,
   `GroupSection$ContentPanel` vacuous branch). None affect behaviour; cleaning
   them is optional. The former mutable `GuiPresets.NAMES` list is fixed (A11).
8. **Out-of-scope dead code / silent-ignore behaviours** listed in section 3
   remain until the owning workstreams pick them up; they are warnings, not
   data-corruption bugs.
9. **GUI preferences are a best-effort convenience store** under
   `~/.umbra/gui.properties`; a read-only home is silently tolerated, and two
   concurrent GUI instances can race on the temp-file replace (last writer
   wins). Corrupt files fall back to defaults (tested).
10. **`--inspect` reports entry-level counts**: a duplicate class entry is
    counted twice in `transformableClasses` although the protection writer keeps
    the first occurrence (the warning text documents the dedupe). This is a
    reporting nuance, not a transformation bug.
11. **Process cancellation is not covered by an automated audit check**:
    SIGINT/cancelled runs map `CancellationException` to exit code 130 in
    `Main` (Lead's change) and the GUI cancel button is only covered
    structurally by `GuiSelfTest`; exercising a real cancel race needs to
    interrupt a running protection run and is left to the QA matrix on the
    release binary.
12. **Relative paths** resolve against the process working directory (CLI) and
    the configuration-file directory (YAML); this is tested for the CLI
    (`AuditTest` `cli-paths-and-outputs`) but the interaction of a relative
    `-c` path with relative `input:`/`output:` entries is documented behaviour,
    not changed by this audit.
