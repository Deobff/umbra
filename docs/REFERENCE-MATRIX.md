# Reference capability matrix — nine tools studied for Umbra 3.0

Companion to [PLAN-3.0.md](PLAN-3.0.md); workstreams are referenced as `WS1`…`WS6`.

## Method and evidence rules

* Everything below is static inspection of files under `混淆器/`. **No reference tool was executed**, no protected artifact was decompiled, and no third-party code was copied. Behaviour claims are limited to what the sources/docs state.
* `zkm27.jar` was listed with `C:\Program Files\Zulu\zulu-8\bin\jar tf` / `javap` and extracted to a temp directory (source jar untouched) to read its bundled help pages and class names. Versions come from build files/manifests; unreadable or absent files are listed in the final section, never guessed.
* Matrix legend: **Y** implemented and evidenced, **P** partial/opt-in/side-effect only, **–** absent.
* Umbra baseline: the tree already reports `VERSION = "3.0.0"` (`Umbra/src/main/java/io/umbra/Main.java:29`) and `PLAN-3.0.md` is marked "executed", so the "Umbra 2.0" column comes from `docs/RELEASE_NOTES.md` (2.0.0) + `README.md` with the rule "if PLAN-3.0 lists it as *new/upgraded* in WS1-WS3, 2.0 did not have it".

## 1. Zelix KlassMaster 27 — `混淆器/zkm27.jar`, `混淆器/ZelixKlassMaster-27-27.0.1/`

**Version/type/licence.** Commercial closed-source Java obfuscator. The manifest has only `Main-Class: com.zelix.ZKM`; bundled help pages carry `Copyright 2026 Zelix Pty Ltd` (`.../src/main/resources/com/zelix/000.html`). Licence machinery is in `com/zelix/klassmaster/license/` (`LicenseCheckBase`, `LicenseDetails`, `EvaluationExpiredException`, `EncodedKeyTable`, `ObfuscatedLongDecoder`), and `demo/ZKM27-eval.jar` is the evaluation build. No EULA ships here.
**Caution:** `ZelixKlassMaster-27-27.0.1/` is not a vendor distribution — it is a Gradle project that rebuilds a `com.zelix.ZKM` jar from a reconstructed source tree (`build.gradle` `mainClass`, prebuilt `src/main/resources/zkm-templates/**/*.class`), and `entry-times.tsv` opens with "local time the entry has in the original ZKM.jar". **Architecture.** One monolithic engine (`engine/ObfuscationEngine.class`, 213 KB) behind `ZkmApiBase`; a JavaCC script front end (`script/ZkmScriptParser*`, `script/parser/ast/AST*`), a Swing GUI (`ui/**`: "Build Helper", class browser, exclusion wizards), a change-log subsystem (`changelog/**`, `ZKMChangeLog.java`), and a large XML/resource rewriter layer (`xml/**`).

* Integer and long constant encryption (`obfuscator/constants/IntegerConstantEncryptor`, `LongConstantEncryptor`, `IntEncryptionStorageKind`, `LookupStrategySwitchMap`).
* Flow `none/light/normal/aggressive` (`obfuscator/flow/FlowObfuscationManager`, `FlowSplitCandidate`, `GeneratedCodeBlock`, `GeneratedMethodChunk`, `OpaquePredicateField`, `StaticInitCalleeAnalyzer`) and exception obfuscation `none/light/heavy` (`obfuscator/exceptions/ExceptionObfuscator`).

* Auto reflection handling with a hash-keyed lookup mapping (`obfuscator/reflection/AutoReflectionHandler`, `ValueFlowTracker`, `FindFieldNameTranslator`, `GetMethodReflectionStub`) and script statements `accessedByReflection` / `accessedByReflectionExclude`.

* Metadata control: delete unknown/annotation/exception/source-file/deprecated attributes; line numbers `delete|scramble|keep`; LVT `delete|keep|obfuscate`; keep generics/inner-class info; preverify; keep balanced locks; archive compression; open nested archives.

## 2. BytecodeVM 2.2.3 — `混淆器/BytecodeVM-2.2.3/`

**Version/type/licence.** `version = '2.2.3'` (`build.gradle`); JDK 21 build, emits Java 8 class files (README 34-37). **No LICENSE file**; README line 9 says "intended for demonstration purposes only … not suitable for production use" and credits GPT-5.5/5.6.

**Architecture.** ASM 9.7 + picocli + snakeyaml. Method bodies are lowered to a virtual instruction stream (`data/vminsn/*`, `tools/VMMethodCompiler`, `VMMethodSegmenter`), a VM is generated (`generator/virtualization/VMGenerator.java`, 237 KB; `VMSetGenerator`, `CodePoolGenerator`), and the program is executed by generated interpreter branches (`vminterpret/impl/**`).

**VM design specifics (verified).**

* 17 concrete structures + 6 automatic tiers in `enums/VMStructure.java`: `SIMPLE_DISPATCH, DISTRIBUTED_DISPATCH, MULTIPLE_DISPATCH, THREADED_DIRECT, THREADED_INDIRECT, CALL_THREADED, RECURSIVE, CONTINUATION_PASSING, OBJECT, POLYMORPHIC, SELF_MODIFYING, REGISTER_BASED, DATA_FLOW, GRAPH, FSM, EVENT, COROUTINE`; tiers `LOW/MEDIUM_LOW/MEDIUM/MEDIUM_HIGH/HIGH/ANY` resolved through a shuffled 12-item bag (`resolveAuto`).
* Opcode coverage ≈ the whole JVM: `vminterpret/impl/{array,constant,control,conversion,field,invoke,local,lock,math,object,Stack}` (`InvokeDynamicBranch`, `SwitchBranch`, `NewArrayBranch`, `MonitorBranch`, dup/swap/pop, all numeric math).
* Payload/encoding keys (README "Options"): `perMethodOpcodeMap`, `encryptOperands`, `virtualizeInstructionAddresses`, `splitCodeStreams`, `shuffleInstructionBlocks`, `shuffleConstants`, `bindConstantsToOperands`, `dynamicCodePoolBuild`, `dynamicStateKey` ("block-entry state capsules and a rolling per-record key chain"), `virtualControlFlowGraph`, `obfuscateDispatch`, `dynamicConstantDecrypt`.
* Superinstructions: `superInstruction`, `superInstructionCombineRange: [2,5]`, `superInstructionMode: RANDOM|PATTERN|HYBRID`, `superInstructionMaxHandlers: 128`, `superInstructionMinFrequency: 2`.
* Decoys `obfuscateInterpretBranch` / `interpretBranchCases: 3`; integrity `vmIntegrityCheck`, `vmIntegrityCheckRatio`, `vmIntegrityRecheckInterval`.
* Allocation: `createMode ONE_FOR_ALL|PER_METHOD|PER_CLASS|PER_PACKAGE`, `location SAME_PACKAGE_AS_TARGET|NEW_PACKAGE|ONE_PACKAGE`, `renameMode`, `interpretMode`.
* Selection DSL: per-feature `includes`/`excludes` with `class:`, `method:*(*)*`, `field:`, annotation selector `@Sensitive`, `;` conjunction.
* Presets: `DISABLED, SIMPLE, CODE_POOL_ONLY, FAST, LIGHT, BALANCED, INTEGRITY_FOCUSED, STRONG, EXTREME, RANDOMIZED` (any concrete structure name also works as a preset).
* Delivery: `init/validate/inspect/protect/watermark`, JSON inspection report (seed, input/output SHA-256, per-method VM assignment, skip reasons), exit codes 0-6, annotation SDK (`sdk/`: `@Virtualize`, `@ProtectClass`, `@InlineField`, `@InlineFinal`, `@DoNotVirtualize`, `@SuperInstructionOptions`, `@VMOptions`, watermark capsules).
* Input transforms: `preEncryptStrings` (per-site encrypted integer data, adaptive budget), `preEncryptNumbers`, `constantFix` (`ConstantValue` → `<clinit>`), member inlining (README marks `inlineFields`/`inlineCalledProtectedMethods` "UNSAFE"), `virtualizeConstructors`, `virtualizeInvocationBridges`, watermarks.

**Adoptable.** Superinstruction fusion (same idea as WS3.1 `vm2.fusion`; the `combineRange`/`maxHandlers`/`minFrequency` knobs and the PATTERN/HYBRID split are worth copying as *design*); the rolling per-record key chain as a stronger descendant of VM2's per-method opcode permutation; the `inspect` + JSON report contract for CI; per-feature include/exclude instead of one global selector.
**Risks.** Explicitly non-production ("hundreds of times slower"), no licence, no strength evidence of its own; the 17 structures are breadth over depth (several differ only in dispatch shape).

## 3. JNIC-Virtualization-main — `混淆器/JNIC-Virtualization-main/`

**Version/type/licence.** Not an obfuscator. README: "a tool that can dump native library from JNIC obfuscated jars and add a compatible costume loader to it." No licence file; `lib/asm-9.6.jar`, `lib/asm-tree-9.6.jar`; ~22 KB of source total.

**Architecture.** `src/Main.java` (CLI `<JNIC Obfuscated Jar> [Dump DLL true/false]`), `src/DLLDumper.java` (locate and extract the embedded native library), `src/ProcessLoaderClass.java` (rewrite/generate a loader class with ASM), `src/Compiler.java`, and a template `loader.java` with placeholders `*PACKAGE_NAME*`, `*NATIVE_LIBRARY_NAME*`, `*VERIFICATION_CODE*`.

**What it proves about JNIC-style protection (anti-dump relevance).** The template shows the JNIC runtime contract: the native library is stored as a class-path resource under a fixed name, copied to a temp file `ProtectedByYumeCloud_*.ycvm`, and loaded with `System.load(file.getAbsolutePath())` in a static initializer, after a `*VERIFICATION_CODE*` insertion point and a banner ("Obfuscation Powered By YumeCloud"). That design is dumpable: the library exists in plaintext on disk before `System.load`, and a rebuilt/costume loader can drive it without the original bindings — which is exactly what this tool automates (dump the DLL, then swap in a compatible loader).

**Adoptable.** None of the code — the *attack model* is the specification for WS3.2: (a) never leave a decrypted library on disk longer than necessary (memory-load or delete-on-load), (b) fingerprint/integrity-check the library before and after load, (c) verify the native-method backfill table so a dumped library cannot be re-bound by an attacker loader, (d) treat a fixed resource name and a fixed temp-file prefix as a fingerprinting gift to attackers.
**Risks.** This is an offensively oriented utility aimed at a third-party product (JNIC); studying it is fine, using it against software you do not own is not. No code reuse of any kind.

## 5. native-obfuscator 3.5.5r — `混淆器/native-obfuscator-3.5.5r/native-obfuscator-3.5.5r/`

**Version/type/licence.** Java→C++ transpiler for JNI (README line 1). **GPL-3.0** with an "Output exception" that frees only the emitted runtime files (`native_jvm.*`, `string_pool.hpp`, the generated Loader, `cppsnippets.properties` fragments). **Risks.** GPL-3.0 is copyleft — copying any of it into Umbra would relicense Umbra, and the output exception is narrow. It is a transpiler, not a protector, and its own README says to pair it with VMProtect/Themida/obfuscator-llvm.

## What "commercial-grade" requires that the references show

1. **"Never break a valid input" is an engineering feature, not a slogan.** KBox rolls a failed class back to its original bytes while still remapping names (`docs/ARCHITECTURE.md`); native-obfuscator writes through `SafeClassWriter`/`ClassMetadataReader`; BytecodeVM verifies every emitted class with ASM and exits `6` on failure; ZKM keeps inner-class/generics information and preverifies. Umbra 3.0's WS1 + verifier-gated rollback is the same requirement at a larger scope.
2. **A stable, exportable mapping is a product feature.** ZKM's change log + stack-trace translator, KBox's `useMapping`/`mappingFile`, Zipit's `print_mappings`, native-obfuscator's mapping output. Without it customers cannot ship patches or read crash reports. Umbra has mapping export/import and `MappingDiff` — keep it in the contract and document it as such.
3. **Every protection knob must be measurable and documented per key.** KBox documents ~70 keys one by one and publishes byte-growth tables plus CFR evidence (`docs/STRENGTH-REPORT-2026-10-15.md`); BytecodeVM emits a JSON plan with seed, hashes, per-method VM assignment and skip reasons; ZKM's help explains every list item's trade-off. PLAN-3.0's rule "no claimed number without a run" is the same bar.
4. **Selection/exclusion languages decide usability.** ZKM scripts (`accessedByReflection`), KBox `keepPrefix`/`keepMember`/`bodyExcludePrefix`, BytecodeVM per-feature matchers (`class:`, `method:*(*)*`, `@Annotation`), native-obfuscator whitelist/blacklist with `*`/`**` and "list beats annotation" precedence, OpenYCP `include/exclude` with `#` member selectors, Zipit `--keep`/`flatteningExclude`. Umbra's `RuleSet`/`Glob` + keep rules must reach this expressiveness before 3.0 is called commercial.
5. **Graceful degradation, not a single point of failure.** KBox layers VMP → JNIC → BFVM with fallbacks (`failOnNativeError=false`); native-obfuscator switches loader mode per platform; PhantomShield exposes `null_safety`; Umbra's native path already falls back to Java. A tool that fails the whole jar when one method cannot be protected is not shippable.
6. **Licensing is part of the product surface — and "offline" is a differentiator.** ZKM ships a key table and evaluation expiry; Zipit ships RSA licences + a licence server + HWID binding; KBox has optional `lic*` keys; PhantomShield phones home and gates features by user group; OpenYCP ships an auth-server module (missing). The references show the server variant is common *and* a liability (missing modules, plain HTTP, HWID lock-out). Umbra can credibly promise "no network, no phone-home".
7. **Distribution is part of "commercial":** build plugins (Zipit Gradle/Maven, KBox Maven, ZKM Ant), signed/checksummed artifacts (`Zipit/SHA256SUMS`, `zipit-sbom.json`), a GUI for non-CLI users, and English documentation. Umbra 3.0's WS5 + WS7 (zip + `SHA256SUMS`) are the same list.
8. **State the limits out loud.** BytecodeVM says "demonstration only"; native-obfuscator says "does not particularly obfuscate"; KBox lists "three things we cannot prevent"; PLAN-3.0 requires residual limitations in the report. No reference claims a security proof, and neither should Umbra.
